# Задание 3. Трейсинг

### Проанализируйте систему компании

На данный момент система не является распределенной. По этому запрос фактически не переходит из одного сервиса в другой. По этому для Shop API считаю что трейсинг не требуется. А вот для сервиса CRM API и MES API требуется, так как там происходит взаимодействие через брокер сообщений.

Данные для трейсинга:
- идентификатор реквеста(далее спан родительского сервиса)
- идентификатор заказа
- идентификатор менеджера 
- идентификатор оператора

### Мотивация

Добавление трейсинга поможет отследить и выявить причины просроченных и потерянных заказов.

Метрики, на которые влияет добавление трейсинга:  
- скорость обработки заказов  
- удовлетворённость клиентов  
- количество просроченных заказов  
- количество потерянных заказов

### Предлагаемое решение

Для трейсинга буду использовать Jaeger. В монолите необходимо реализовать минимальные доработки, которые позволять передавать данные между сервисами. Это касается монолита CRM API и MES API. Для работы сервиса необходимо развернуть контейнер с Jaeger.

### Компромиссы

В данном случае доработки не должны быть дорогостоящими, так как есть разработчики как на Java, так и на C#. Для трейсинга необходимо добавить middleware. Думаю, это не составит большого труда. Добавление трейсинга необходимо, чтобы понять, на каком этапе теряются заказы.

### Аспекты безопасности

Снаружи доступа к системе не будет — всё будет работать в рамках внутренней локальной сети. Для работы с сервисом можно предусмотреть авторизацию.
